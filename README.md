## 1. 库与目录布局

- 库根只保留 Obsidian 与 Git 配置，以及本概要：`.obsidian/`、`.gitattributes`、`.gitignore`；正文分别放在 `note/` 与 `handover/`。
- `note/` 是长期知识笔记，文件名 `NN名称.md`，由 [[00总览]] 导航。
- `handover/` 是阶段性交接文档，文件名带日期，由 [[00总览-2026-10-05]] 索引。
- 偏离说明：按 [[05Command]] 第 8.2 节，正文一律放 `note/`；`handover/` 是有意偏离，本 README 按用户要求放在库根，同属偏离，理由见第 6 章。

## 4. 写作规范要点

据 [[05Command]]，全库通用：

- 标题：H1 唯一且不编号；H2 为 `1.`，H3 为 `1.1`，H4 为 `1.1.1`，最多到 H4；编号连续，不跳号、不重号。
- 分隔线：只在每个 H2 章节末尾加一条 `---`，前后各空一行，最后一章也加，文档以 `---` 结束。
- 空行与列表：标题、代码块、表格、引用块前后各空一行；无序列表用 `-`，缩进 2 个空格，嵌套不超过 3 层。
- 排版：中文与英文、数字之间加一个半角空格；中文用全角标点；术语按术语表统一写法，同篇不得出现两种写法。
- 代码块：必须标注语言且语言名小写；命令写清执行环境；破坏性命令必须给出备份或回滚方式。
- 链接：库内用双链 `[[...]]`，指向标题用 `[[文档#标题]]`，外部链接保留原始 URL。
- 文件与交付：正文放 `note/`；UTF-8 无 BOM、LF 行尾、末尾一个换行；不使用 YAML frontmatter，元信息写在标题下的引用块。
- 目录与变更记录：章节数达到 8 章或正文超过 300 行时应当加目录；操作类文档应当在文末加变更记录表。
- 提交状态表述：不得写入会随提交动作变化的事实（未提交清单、提交笔数、提交序号），改为指向 `git log`、`git status` 的表述；判据是稳定性，不是具体程度。
- 敏感信息：不得出现真实 token、密码、私钥、cookie、内网 IP 与内网主机名；真实用户名用 `%USERPROFILE%` 等占位符。
- 交付前：文末附交付前自查清单，逐项核对标题编号、分隔线、代码块语言、脱敏、编码与目录。

## 5. 交接文档规范要点

据 [[01交接文档写作格式-2026-10-05]]，只约束 `handover/` 下的文档：

- 适用范围与优先级：与 [[05Command]] 同时适用，冲突时以本篇为准；无法满足某条要求时必须在回复中说明，不得静默忽略。
- 文档骨架：九章顺序固定，依次是状态摘要、交付物与指纹、变更清单、决策与理由、已验证与未验证、回滚与恢复、未决事项与下一步、复现方法、环境速查；确无内容的章节写「无」并说明原因，不得删除。
- 内容硬要求：交付物给路径、精确字节数、完整 SHA-256、行数、编码与行尾；变更清单的增删行数须与 `diff` 一致；每条决策写全决策点、备选项、影响与结论，并记录被否决的选项；已验证与未验证分栏，推测显式标注；回滚命令标注执行环境。
- 格式收紧：元信息必须含「交接状态」与「接手方需要先知道」；章节数达到八章时目录由「应当」收紧为「必须」；差异、命令、脚本一律用带语言标注的代码块。
- 敏感信息：命令输出与日志写入前先脱敏；库内提交前先扫描后暂存，判据是「只拦新增暴露」。
- 可复跑资产：脚本与文档分离，作为独立文件放在 `handover/` 并双链引用；PowerShell 脚本存 UTF-8 带 BOM，且交付前实测可运行。
- 交付前：文末附自查清单，比 [[05Command]] 的清单额外要求状态摘要可独立说明现状、每条决策含被否决项、回滚命令标注环境等。

## 6. 规范的优先级与偏离

- 优先级链：用户当次要求 > [[01交接文档写作格式-2026-10-05]] > [[05Command]] > 既有写法与工具默认习惯。
- 约束范围：`note/` 与库根文档只受 [[05Command]] 约束；`handover/` 同时受上述两套规范约束，其中交接文档特有的要求以 [[01交接文档写作格式-2026-10-05]] 为准。
- 已知偏离：`handover/` 不放在 `note/`、不使用 `NN名称.md`；本 README 放在库根并命名为 `README.md`。两处均为用户明确要求，属 [[05Command]] 第 1.3 节要求显式说明的偏离。
- 使用建议：写新文档前先确认它属于哪个目录，再套用对应规范；两套规范冲突时按上面的优先级链判断。
