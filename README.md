## 1. 库与目录布局

- 库根只保留仓库配置与库级说明：`.obsidian/`、`.gitattributes`、`.gitignore`、本概要 `README.md`、`AGENTS.md`，以及项目级 Skills 目录 `.agents/`（含清单 `skills-lock.json`）；正文分别放在 `note/` 与 `handover/`。
- `note/` 是长期知识笔记，文件名 `NN名称.md`，由 [[00note总览]] 导航。
- `handover/` 是阶段性交接文档，文件名带日期，由 [[00handover总览]] 索引。
- `templates/` 是生成文档用的模板与示例数据，不属知识正文，文件名用英文小写加连字符，由 [[00模板说明]] 说明。

---

## 2. note 目录

- 定位：记录 Git/GitHub、Obsidian 同步、Skills 与 DSH 插件安装、Python 环境等工具操作与规范。
- 命名：`NN名称.md`，`NN` 为两位序号；英文名称不用下划线、各单词首字母大写，中文名称连写；新增笔记顺延编号。
- 篇目清单以 [[00note总览]] 为准，本概要不再重复登记。

---

## 3. handover 目录

- 定位：把已完成或进行中的工作移交给未来的自己或 AI，只写当前状态、决策与理由、未决事项与复现方法，不抄对话过程。
- 命名：`NN主题-YYYY-MM-DD.md`，`00` 恒定留给总览，`01` 为写作规范，交接记录从 `02` 起按两位顺序号顺延；总览（`00handover总览`）、规范（`01交接文档写作格式`）与当前状态入口（`当前状态.md`）不带日期、不占编号，属命名例外；一个阶段一份文档，同一主题进入新阶段时新建文档，不回写旧篇。
- 文档清单以 [[00handover总览]] 为准，本概要不再重复登记。
- 维护要求：新增、改名或删除文档后，必须同步更新 [[00handover总览]] 的日期索引与摘要。

---

## 4. 写作与交接规范

- 全库 Markdown 规范以 [[05Markdown规范]] 为准，`handover/` 交接文档规范以 [[01交接文档写作格式]] 为准，提交与文档同步的规则以 [[10提交与文档同步规则]] 为准；冲突时的优先级见下一章。
- 本概要不再登记这三套规范的要点副本：副本会随规范修订而过时，需要细节时直接读上述三份文档。

---

## 5. 规范的优先级与约束范围

- 优先级链：用户当次要求 > [[01交接文档写作格式]] > [[05Markdown规范]] > 既有写法与工具默认习惯；提交与同步另按 [[10提交与文档同步规则]] 执行，该篇是规则一的正本，不参与写法优先级。
- 约束范围：`note/` 与库根文档只受 [[05Markdown规范]] 约束；`handover/` 同时受上述两套规范约束，其中交接文档特有的要求以 [[01交接文档写作格式]] 为准；`templates/` 的模板与示例数据属工具资产，写法与命名见 [[00模板说明]]，不套用 `note/` 的编号约定；提交与文档同步按 [[10提交与文档同步规则]] 执行，其第 4 章是提交流程的现行版本。
- 库根说明：`README.md` 与 `AGENTS.md` 按用户要求放在库根，属库级说明，不适用 `note/` 的 `NN名称.md` 命名；各目录均按 [[05Markdown规范]] 第 8.2 节的目录分工存放，当前没有结构性偏离。
- 使用建议：写新文档前先确认它属于哪个目录，再套用对应规范；两套规范冲突时按上面的优先级链判断；提交前按 [[10提交与文档同步规则]] 第 4 章的流程执行。
