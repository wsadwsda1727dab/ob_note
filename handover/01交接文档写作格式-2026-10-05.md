# 交接文档写作格式

> 文档名称：交接文档写作格式

## 1. 适用范围与优先级

### 1.1 适用范围

- 本规范适用于 `handover/` 下的全部交接记录类文档，即记录某一工作阶段状态的文档。
- 本目录另有两类不属交接记录：总览 `00`（索引）与写作规范 `01`（规则）；两者按各自职责维护，不套用第 3 章的九章骨架。
- 交接文档的用途是把某一工作阶段在特定交接时点的状态移交给未来的自己或未来的 AI，不是记录对话过程。

### 1.2 与 [[05Command]] 的关系

- 交接文档**必须**同时遵守 [[05Command]] 的全部格式规则：标题层级与编号、章节末尾分隔线、空行、列表缩进、中英文之间的空格、标点、表格、代码块语言标注、术语写法。
- 本规范只补充交接文档特有的要求，不重复定义格式规则。
- 两者冲突时，以本规范为准。

### 1.3 冲突优先级

1. 用户当次的明确要求
2. 本规范
3. [[05Command]]

- 无法满足本规范的某条要求时，**必须**在回复中说明是哪一条、为什么不满足，**不得**静默忽略。

### 1.4 为什么不抄对话

- 对话里有大量过程噪声（试错、失败尝试、重复操作），逐字存档会把噪声固化成事实。
- 结论分散在多轮里，接手方需要的是可直接执行的当前状态，而不是推演过程。
- 对话原文已存在于 DSH 的会话记录中，再抄一份是重复存储，且必然过时。
- 交接文档只写四样东西：当前状态、决策与理由、未决事项、复现方法。

## 2. 存放位置与命名

### 2.1 存放位置

- 交接文档统一放在 `ob_c1/handover/`。
- 这是对 [[05Command]] 第 8.2 节「正文一律放在 `note/`」的**有意偏离**：交接文档是阶段性产物，与 `note/` 下的长期知识分开存放，避免污染笔记编号序列。
- 该偏离经用户当次明确要求确认；若以后要求改回 `note/`，**必须**同步迁移全部文件并更新双链。

### 2.2 文件命名

- 文件格式：`NN主题-YYYY-MM-DD.md`，`NN` 为两位顺序号。
- `00` 恒定留给本目录的总览（[[00总览-2026-10-05]]），使其排在最前；其余文档从 `01` 起按新增顺序顺延，新增时取当前最大序号加一。
- 主题用中文连写，不加下划线；英文缩写保留术语表写法。
- 示例：`00总览-2026-10-05.md`、`01交接文档写作格式-2026-10-05.md`、`02DSH全局指令安全边界-2026-10-05.md`。
- 本目录**不使用** [[05Command]] 第 8.2 节的 `NN名称.md` 编号形式：顺序号之后必须接主题与日期，由顺序号承担排序、日期承担版本标识。
- 改名或调整顺序号后，**必须**同步更新 [[00总览-2026-10-05]] 的索引，以及引用它的双链。
- 文件名中不得出现 `\ / : * ? " < > |`，也不得有首尾空格。

### 2.3 一个阶段一份文档

* 每份交接文档对应一个明确的工作阶段或交接时点，形成后原则上作为**阶段性快照冻结**，不因后续工作进展而持续改写。
* 同一主题后续进入新的工作阶段时，应新建交接文档记录新的状态、决策、验证结果与未决事项，不覆盖或改写上一阶段的历史记录。
* 新增交接记录类文档时，**必须**在元信息「承接自」写上一阶段交接文档的双链，无上一阶段写「无」。
* 仅当发现原文档存在**事实错误、格式错误或结构性遗漏**，且修正不会改变该阶段的历史状态时，才允许对已形成的交接文档进行更正；如更正会改变历史判断，应新建后续交接文档说明变化原因。

## 3. 文档骨架

```markdown
# <交接主题>

> 文档名称：<交接主题>
> 交接范围：<覆盖的文件、系统与时间范围>
> 交接状态：<已完成 / 部分完成 / 进行中 / 已阻塞>
> 接手方需要先知道：<一句话，最重要的那一条>
> 承接自：<上一阶段交接文档的双链；无则写「无」>
> 最近更新：YYYY-MM-DD
> 关联文档：[[...]]

**目录**

- [[#1. 状态摘要]]
- [[#2. 交付物与指纹]]
- [[#3. 变更清单]]
- [[#4. 决策与理由]]
- [[#5. 已验证与未验证]]
- [[#6. 回滚与恢复]]
- [[#7. 未决事项与下一步]]
- [[#8. 复现方法]]
- [[#9. 环境速查]]

## 1. 状态摘要

## 2. 交付物与指纹

## 3. 变更清单

## 4. 决策与理由

## 5. 已验证与未验证

## 6. 回滚与恢复

## 7. 未决事项与下一步

## 8. 复现方法

## 9. 环境速查

---
```

- 交接状态取值四选一：已完成、部分完成、进行中、已阻塞；已交付主体、仍有后续项未做时用「部分完成」。
- 元信息**必须**含「承接自」：承接上一阶段时写上一份交接文档的双链，本篇为同主题首篇或非交接记录类文档时写「无」。
- 总览 `00` 与写作规范 `01` 不属交接记录，按各自职责维护，不套用本节骨架，两者列为跨篇引用。
- 操作类交接可在文末追加一章「变更记录」，格式见 [[05Command]] 第 8.7 节。

## 4. 各章节内容要求

### 4.1 状态摘要

- 三行以内说明：现在是什么状态、接手方是否需要立刻行动、最重要的一条结论。
- **必须**做到只看这一节就能判断要不要继续往下读。

### 4.2 交付物与指纹

- 逐个列出**本篇自己的**产出文件或改动文件，**必须**含路径、字节数、SHA-256、行数、编码与行尾。
- **不得**登记其他交接文档的指纹：各篇是阶段性快照，其数值属各篇第 2 章自持；跨篇登记会在任一篇改动时集体过时，并引入「先定稿、后取哈希」的顺序约束。其他文档的新增与删除由 Git 提交记录承担。
- 按冻结规则改了元信息「最近更新」或第 7、10 章后，本节登记的 SHA-256 即不再对应磁盘文件；此时**不得**回写本节（第 2 章不属可改范围），改动事实记入第 10 章变更记录，需要当前值时按路径重新计算。

| 项目 | 要求 |
|---|---|
| 路径 | 按第 6 章脱敏 |
| 字节数 | 精确值，不写「约」 |
| SHA-256 | 写完整 64 位十六进制，便于逐字节核对 |
| 行数 | 与换行计数口径一致，末行无换行时不计为一行 |
| 编码与行尾 | 例如 UTF-8 无 BOM、LF |

### 4.3 变更清单

- 逐条列出改了什么：位置、改前、改后、原因。
- 差异用 `diff` 代码块承载，不要贴整份文件。
- 增删行数**必须**与 diff 一致，便于第三方核对。

### 4.4 决策与理由

- 每条决策**必须**写全四项：决策点、备选项、各自影响、结论。
- **必须**记录被否决的选项与否决理由，否则接手方会重复讨论同一件事。
- 结论若可反悔，写明反悔需要改哪里。

### 4.5 已验证与未验证

- **必须**分成两栏，不得混写；这是交接文档里最影响接手判断的一节。
- 已验证：写明验证方式与证据，例如命令、输出、哈希、实测结论。
- 未验证：写明为什么没验证、是否影响使用。
- 推测**必须**显式标注为推测，不得写成结论。

### 4.6 回滚与恢复

- 给出备份路径（脱敏）与可直接执行的恢复命令。
- 命令**必须**标注执行环境，见 [[05Command]] 第 6.2 节。
- 说明什么情况下应当回滚，以及回滚会丢失什么。

### 4.7 未决事项与下一步

- 每项写四件事：事项、前置条件、优先级、由谁决定。
- 分「等用户决定」与「可自行推进」两类，避免接手方把该问的当成该做的。
- 某项闭环后，两处的「事项」文字**必须**同步加删除线（[[00总览-2026-10-05]] 第 6 章的汇总表与本文档第 7.1 节各一处），行保留不删；规则见 [[05Command]] 第 14 章。

### 4.8 复现方法

- 给出可复跑的命令或脚本骨架，以及它们的存放位置。
- 脚本与文档分离：脚本放独立文件，文档只写调用方式与预期输出。
- 复现所需的密钥、账号、环境变量一律用占位符，不写真实值。

### 4.9 环境速查

- 记录接手方需要知道的环境事实：沙箱策略、权限能力、网络出口、工具版本、路径约定。
- 每条**必须**标注「已验证」或「推测」。

## 5. 格式细则

- 全部格式规则继承 [[05Command]]，此处不重复。
- 交接文档在其之上收紧或补充如下：
  - 元信息**必须**含「交接状态」「接手方需要先知道」与「承接自」三个键。
  - 章节数达到八章时**必须**加目录；[[05Command]] 第 8.5 节为「应当」，交接文档收紧为「必须」。
  - 差异、命令、脚本一律用带语言标注的代码块，不得用无标注块代替。
  - 表格单元格内不换行；内容过长改用列表或拆分表格。
  - 文档以最后一章的 `---` 加换行结束，见 [[05Command]] 第 3 章。
  - 哈希、路径、命令用行内代码或代码块，不要写成普通正文。
  - 文档中**不得**写入会随提交动作变化的事实：未提交清单、提交笔数、提交序号；这类信息写成指向 `git log`、`git status` 的表述，避免提交动作本身让文档失真。该要求已提升为全库规则，见 [[05Command]] 第 13 章，此处只作提示。

## 6. 敏感信息处理

- 继承 [[05Command]] 第 9 章，并对交接文档收紧如下。

### 6.1 绝对禁止出现

- 真实 token、密码、私钥、cookie、会话标识。
- 内网主机名与真实用户名。

### 6.2 路径写法

- 统一写成占位形式：`%USERPROFILE%`、`C:\Users\<用户名>`、`<主机名>`。
- 确需记录绝对路径时只写盘符与目录层级，不写用户名。

### 6.3 写入前必查

- 命令输出、日志片段写入前**必须**先脱敏，不能整段照抄。
- 交接文档常出现「读过哪些文件」，写入前**必须**逐条检查：该路径、该文件名本身是否泄露隐私或敏感主题。
- 若交接内容涉及凭据的存在，只写其位置与用途，**不得**写内容，也**不得**把凭据读取到上下文后转述。

### 6.4 提交前扫描

- 库内提交前**必须**先扫描、后暂存；有命中即中止，不执行 `git add`。
- 判据是“只拦截新增暴露”：命中的值若已存在于 `HEAD`（含重命名前的旧路径）则为既存，放行并记录；出现任何新值一律中止。
- 硬禁级规则：token、私钥块、键值型凭据、内网 IP、本机主机名；应当级规则：真实用户名、邮箱地址。
- 报告只输出文件、规则与命中次数，**不得**回显命中内容。
- 已知误报：邮箱规则会命中 SSH 克隆地址里的固定用户名，判据按字面量确认，常量可列入白名单。
- 只提交到本地；推送是独立动作，需单独授权。
- 完整流程见 [[03ob_c1提交流程-2026-10-05]]。

## 7. 可复跑资产

- 与交接内容配套的脚本、校验片段**应当**作为独立文件放在 `handover/` 下，并在文档中用双链引用。
- 图片、PDF、压缩包等附件按 [[05Command]] 第 8.6 节放在 `note/attachments/`，不要放在 `handover/`。
- 脚本**必须**可独立运行，不依赖文档里的手工步骤；前置条件写在脚本头部注释中。
- 脚本文件名同样带日期，格式：`主题-YYYY-MM-DD.ps1`。
- PowerShell 脚本**必须**存为 UTF-8 **带 BOM**：Windows PowerShell 5.1 读取无 BOM 的非 ASCII 脚本会按 ANSI 解码，导致中文注释乱码并报语法错误。这是对 [[05Command]] 第 8.3 节「不带 BOM」的有意例外，该节约束的是 Markdown 文档。
- 脚本的可运行性**应当**在交付前实测一次，不能只靠语法解析通过；本机默认执行策略会拦截未签名脚本，实测时需临时放开。

## 8. 交付前自查

- [ ] 只有一个 H1，且不带编号
- [ ] 章节从 `## 1.` 起连续编号，无跳号、无重号、无跳级
- [ ] 每章末尾有 `---`，前后各空一行，文档以 `---` 结束
- [ ] 元信息含「交接状态」「接手方需要先知道」与「承接自」
- [ ] 状态摘要可独立说明现状
- [ ] 交付物含字节数与完整 SHA-256
- [ ] 第 2 章的 SHA-256 为生成当时的取值，且未在第 7、10 章改动后回写本节
- [ ] 变更清单的增删行数与 diff 一致
- [ ] 每条决策含被否决的选项
- [ ] 已验证与未验证分栏，推测已标注
- [ ] 回滚命令标注了执行环境，并说明适用条件
- [ ] 未决事项写明了前置条件与决定方，并标注「等用户决定」或「可自行推进」
- [ ] 已闭环的项在汇总表与第 7.1 节两处都加了删除线
- [ ] 无 token、密码、私钥、cookie、内网主机名、真实用户名
- [ ] 提交前已按第 6.4 节扫描，且无新增暴露
- [ ] 未写入会随提交动作变化的事实（未提交清单、提交笔数、提交序号）
- [ ] 代码块全部标注语言，语言名小写
- [ ] Markdown 为 UTF-8 无 BOM、LF 行尾、末尾一个换行
- [ ] `.ps1` 脚本为 UTF-8 带 BOM、LF 行尾，且已实测可运行
- [ ] 文件名符合 `NN主题-YYYY-MM-DD.md`
- [ ] 关联双链可跳转，无死链
