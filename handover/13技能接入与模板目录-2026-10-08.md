## 5. 决策与理由

### 5.1 决策点：6 个技能的落地层级

- 备选项：甲，项目级 `.agents/skills/`；乙，全局 `%USERPROFILE%\.codex\skills\`。
- 影响：甲只对本库生效、随库分发，且该目录已在 `.gitignore` 内不进版本库；乙对所有项目生效，与 Obsidian 无关的项目也会加载。
- 结论：选甲，与这批技能只服务 Obsidian 库的定位一致。反悔需按 [[04Skills]] 的方式重装到全局目录。

### 5.2 决策点：`defuddle` 与 `knap` 的安装方式

- 备选项：甲，全局安装 `npm install -g`；乙，改用 `npx` 每次临时调用。
- 影响：甲在 PATH 上加两个命令，批量渲染时无额外下载开销，代价是污染全局环境；乙反之，且 `knap batch` 这类批量场景明显变慢。
- 结论：用户选甲，已装并实测版本与渲染。反悔需执行 `npm uninstall -g defuddle knap`。

### 5.3 决策点：交接文档模板的存放位置

- 备选项：甲，放 `handover/` 下作为可复跑资产，即 [[01交接文档写作格式]] 第 7 章的默认做法；乙，放 `note/` 下顺延编号；丙，另设 `templates/` 目录。
- 影响：甲把跨阶段复用的模板与某一阶段的资产混放，与本目录「一个阶段一份文档」的定位冲突；乙占用 `note/` 编号，而模板不是长期知识正文；丙新增一处目录偏离，需要同步 `README.md` 第 5 章与 `01` 第 7 章。
- 结论：用户选丙；目录定位、命名与用法写在 [[00模板说明]]，偏离说明同步进 `README.md` 与 `01` 第 7 章。反悔需删目录并把规则表述改回甲的写法。

### 5.4 决策点：`templates/` 说明文档的文件名

- 备选项：甲，`templates/README.md`；乙，`templates/00模板说明.md`。
- 影响：甲的路径更常规，但与库根 `README.md` 同名，Obsidian 双链按文件名解析，`[[README]]` 会指向不明；乙与 `note/00note总览`、`handover/00handover总览` 的 `00` 作入口习惯一致，代价是文件名不是常规的 `README`。
- 结论：选乙。

### 5.5 决策点：指纹与交接文档的先后顺序

- 备选项：甲，先生成文档、再取指纹回填第 4 章；乙，先取指纹、再渲染一次成稿。
- 影响：甲的写入动作落在第 4 章，而 [[01交接文档写作格式]] 第 2.3 节规定冻结后可改的只有「最近更新」与「未决事项与下一步」章，甲会违反这条可改范围；乙把取指纹前置，第 4 章一次写对，代价是渲染必须在交付文件定稿之后。
- 结论：选乙；会话中一度提出过的「生成 → 取指纹 → 回填 → 重新生成」作废，理由见第 6 章末条与 `01` 第 2.3 节。

## 7. 回滚与恢复

- 备份路径：本次改动未单独备份；`templates/` 为新增目录，其余文件均在 Git 跟踪范围内，状态以 `git status`、`git log` 为准。
- 何时应当回滚：`templates/` 与新增口径不被接受，或模板渲染引入格式回归时。
- 恢复命令（Windows PowerShell，在库根 `ob_c1` 执行）：

```powershell
git -c safe.directory="D:/User/Documents/Obsidian/ob_c1" status --short
git -c safe.directory="D:/User/Documents/Obsidian/ob_c1" restore --source=HEAD -- "README.md" "handover/01交接文档写作格式.md" "handover/00handover总览.md" "handover/当前状态.md"
Remove-Item -LiteralPath 'D:\User\Documents\Obsidian\ob_c1\templates' -Recurse
```

- 回滚会丢失什么：删除 `templates/` 会丢失模板、示例数据与说明文档，需要按第 5.3 节的结论重做；`restore` 会把四个文档回退到上一次提交的状态，本阶段在其中的改动（含本篇的索引行与汇总行）一并丢失。本篇为新增文件，回滚方式为直接删除该文件。

## 8. 复现方法

- 指纹复核（Windows PowerShell，在库根执行）：

```powershell
$root = 'D:\User\Documents\Obsidian\ob_c1'
$files = @('templates\00模板说明.md','templates\handover-template.md','templates\handover-data.example.json','README.md','handover\01交接文档写作格式.md','handover\00handover总览.md','handover\当前状态.md')
foreach ($f in $files) {
  $p = Join-Path $root $f
  $b = [IO.File]::ReadAllBytes($p)
  '{0}|{1}|{2}|{3}' -f ($f -replace '\\','/'), $b.Length, (Get-Content -LiteralPath $p -Encoding UTF8).Count, (Get-FileHash -LiteralPath $p -Algorithm SHA256).Hash
}
```

- 预期：七行输出与第 4 章逐行一致；任一行不符说明该文件已在本篇之后再次改动，需要当前值时按路径重新计算，不回写第 4 章。

- 模板生成复现（Windows PowerShell，在库根执行）：

```powershell
knap validate templates/handover-template.md
knap render templates/handover-template.md --data templates/handover-data.example.json -o '<输出路径>'
```

- 预期：`validate` 输出 `Template is valid`；渲染结果的结构与本篇一致，具体字节数与 SHA-256 取决于传入的数据。

- 本篇未另附独立脚本或数据文件：数据文件与文档内容一一对应，入库后会成为第二份需要同步维护的副本；校验片段只有数行，可直接按上面两段执行。这偏离 [[01交接文档写作格式]] 第 7 章「脚本应当作为独立文件」的默认做法，理由同前。
