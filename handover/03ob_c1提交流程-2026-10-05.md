## 4. 决策与理由

### 4.1 决策点：扫描与暂存的顺序

- 备选项：甲，先扫描再暂存；乙，先暂存再扫描。
- 影响：乙一旦命中，需要回退索引，容易留下半成品状态；甲的失败路径简单，索引与工作区都保持原样。
- 结论：选甲，并且做成 fail-closed——有命中就中止，`git add` 一次都不执行。
- 反悔方式：若将来把扫描并入提交钩子，顺序问题由钩子统一处理，本节作废。

### 4.2 决策点：判据是“见敏感值即拦”还是“只拦新增暴露”

- 备选项：甲，发现任何敏感值就中止；乙，只拦工作区新出现、`HEAD` 中不存在的值。
- 影响：甲会被历史既存内容永久卡死——本库就存在一个 SSH 克隆地址里的固定用户名，按甲的口径永远无法提交；乙需要逐值比对 `HEAD`，实现稍复杂。
- 结论：选乙，并保留甲的从严侧：任何**新值**无论硬禁级还是应当级一律中止。
- 反悔方式：把判据改回甲即可，代价是先清理历史里已存在的敏感值。

### 4.3 决策点：报告是否回显命中内容

- 备选项：甲，连命中片段一起打印，便于定位；乙，只报文件、规则与次数。
- 影响：甲的命中片段会进入终端回滚缓冲、日志与对话记录，使扫描记录本身变成新的泄漏点。
- 结论：选乙。需要定位时按文件与行号另行查看，不在报告里展开内容。
- 反悔方式：无必要。

### 4.4 决策点：提交是否包含推送

- 备选项：甲，提交后自动推送；乙，只提交，推送单独授权。
- 影响：甲会让未复核的内容直接进入远端历史，而远端历史不易撤回，且远端可能是公开仓库。
- 结论：选乙。推送是独立动作，一律需单独授权，本流程到 `git commit` 为止。
- 反悔方式：若将来远端改为完全可信的私有备份，可考虑自动推送。

### 4.5 决策点：是否把流程做成独立脚本

- 备选项：甲，做成可运行脚本；乙，写成命令骨架，按需内联。
- 影响：甲省手工，但绑 Windows PowerShell 5.1、执行策略、编码三个坑，还要额外维护规则清单文件；本库提交频率低，收益有限。
- 结论：选乙。
- 反悔方式：把第 8 章的命令段存为脚本文件；注意脚本必须存为 UTF-8 带 BOM，否则中文会乱码并报语法错误。

## 6. 回滚与恢复

- 命令在 Windows PowerShell 中执行；下列命令含破坏性选项，执行前先确认目标提交与当前分支。

```powershell
# 尚未推送：撤回最后一次提交，改动保留在工作区
git reset --soft HEAD~1

# 尚未推送：同时撤回暂存，改动回到工作区但不再 staged
git reset --mixed HEAD~1

# 已经推送：不要改写远端历史，改为追加一个反向提交
git revert <提交哈希>
```

- 何时应当回滚：提交信息写错、漏文件、或误把不该提交的内容带进了本地历史。
- 回滚会丢失什么：`--soft` 只动提交记录，不动内容；`--mixed` 会把暂存区清空；`git revert` 会新增一笔提交，原提交仍在历史里。
- 若敏感值已经入库：仅回滚提交不够，它仍留在历史中。需要改写历史，并且**必须同时轮换该凭据**——一旦推送过，就不能再假定它没有被读过。

## 8. 复现方法

### 8.1 标准流程

1. 取得待提交路径清单，含未跟踪目录内的文件。
2. 逐文件比对工作区与 `HEAD` 的命中值，只对新增值拦截；有新增即中止，不暂存。
3. 打印报告：文件、规则、命中次数，不回显内容。
4. 全部通过后暂存，复核暂存统计，再提交。
5. 推送不在本流程内，需单独授权。

### 8.2 命令骨架

```powershell
$repo = 'D:\User\Documents\Obsidian\ob_c1'
$sd = @('-c', "safe.directory=$repo", '-c', 'core.quotepath=false', '-C', $repo)

# 1. 待提交路径（含未跟踪目录内的文件）
$por = @(git @sd status --porcelain=v1 --untracked-files=all)

# 2. 扫描：工作区命中值与 HEAD 命中值逐值比对，只有新值才中止
#    重命名过的文件要连旧路径一起取 HEAD 内容，否则会把改名当成新增暴露

# 3. 通过后暂存与提交
git @sd add -A
git @sd diff --cached --stat
git @sd commit -m '<提交信息>'
```

### 8.3 扫描规则

- 硬禁级：GitHub Token、GitHub PAT、`sk-` 前缀的长密钥、AWS Access Key、私钥块、`password`／`secret`／`api_key` 等键值型凭据、内网 IP、本机主机名。
- 应当级：真实用户名、邮箱地址、第三方中继域名。
- 报告只输出文件、规则与命中次数；**不得**回显命中内容。
- 已知误报：邮箱规则会命中 SSH 克隆地址里的固定用户名（形如 `git@` 加域名）。判定要按字面量确认，不能只看正则是否命中，也可把该常量直接列入白名单。
- 自撞风险：若文档里为了说明规则而写出“规则名本身”，宽松写法可能自撞；规则里的长度阈值（例如密钥至少 20 个字符）能避免这一类自撞。

## 9. 环境速查

- **笔记库 Git**：`ob_c1` 是 Git 仓库，`main` 跟踪 GitHub 上的 `origin/main`；提交与推送是两个独立动作，推送一律需单独授权。已核实。
- **远端比较的口径**：判断领先或落后用的是本地缓存的远端引用；未执行 `git fetch` 时，远端最新提交不可见。已核实。
- **表格会被编辑器重排**：文档经外部编辑器格式化后，表格会补齐空格并把分隔行的破折号拉长，从而产生未提交改动（实测某次多出 68 字节，忽略空白后仅剩分隔行长度变化）。提交前先确认 diff 是否只属这类变化。已核实（触发者推测为 Obsidian 的表格格式化）。
- **库的完整性标签**：库根与 `note`、`handover` 均带 Low 标签，新建对象自动继承。已核实。
- **若要把流程存为脚本**：Windows PowerShell 5.1 要求非 ASCII 脚本存为 UTF-8 带 BOM，且直接调用 `.ps1` 可能被执行策略拒绝，需临时放开。详见 [[02DSH全局指令安全边界-2026-10-05]] 第 9 章。已核实。
