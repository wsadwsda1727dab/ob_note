## 7. 回滚与恢复

- 备份依据：本地 Git 历史中的 `3fd784e` 保存规则改置与改名的历史版本，`3fd784e^` 为该次提交之前的状态；Git 不保存工作区中尚未进入历史的改动，恢复前必须另行备份实际文件。
- 何时应当回滚：发现迁移遗漏、改名引用错误或本篇内容与核实证据不符；一般文字错误优先按冻结规则允许的更正范围处理。
- 只读核对命令（Windows PowerShell，在库根执行）：

```powershell
git show --stat 3fd784e
git diff 3fd784e^ 3fd784e -- note/ handover/ README.md AGENTS.md templates/
git diff -- handover/00handover总览.md handover/当前状态.md templates/00模板说明.md note/10提交与文档同步规则.md
```

- 恢复已进入历史的本阶段提交时，先确认目标、备份后来修改并取得用户授权；以下命令会新增反向提交，不在本次编写中执行（Windows PowerShell，在库根执行）：

```powershell
git revert --no-commit 3fd784e
```

- 使用 `--no-commit` 后仍须核对所有受影响文件、处理冲突、完成索引与引用同步，再按现行提交流程提交。该命令不撤销之后的工作区文字修正，也不自动处理本篇的新建。
- 回滚会丢失什么：反向改动会撤销该提交涉及的规则迁移、改名及关联同步；该提交包含其他文档修改，不宜为一个局部错误整体回滚。
- 本篇与本次入口同步的撤销需按实际 Git 状态制定局部恢复方案。未经备份与明确授权，不执行覆盖、删除、硬重置或历史改写。

- 文件指纹复算（Windows PowerShell，在库根执行；下列片段只读取指定文件）：

```powershell
$paths = @(
  'handover/00handover总览.md',
  'handover/当前状态.md',
  'templates/00模板说明.md',
  'note/10提交与文档同步规则.md'
)
foreach ($path in $paths) {
  $bytes = [IO.File]::ReadAllBytes((Join-Path (Get-Location) $path))
  $text = [Text.UTF8Encoding]::new($false, $true).GetString($bytes)
  $lines = [regex]::Matches($text, "`n").Count
  $sha = (Get-FileHash -LiteralPath $path -Algorithm SHA256).Hash
  '{0}|{1}|{2}|{3}' -f $path, $bytes.Length, $lines, $sha
}
```

- 预期：文件未变更时与第 4 章逐值一致；文件后来更新时出现差异属正常，核对更新原因，不回写历史指纹。
- 结构与改动范围核对（Windows PowerShell，在库根执行）：

```powershell
git diff --check
git status --short
git log -3 --oneline
```

- 预期：空白检查不输出错误；实际改动与提交情况由命令返回，不预先写死数量或状态。
