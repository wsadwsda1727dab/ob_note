### 4.1 决策点：`00总览` 用带日期的文件名还是裸名

- 结论：选甲。
- 反悔方式：改名为 `00总览.md` 并更新引用它的双链（目前仅库内少量引用）。

### 4.2 决策点：`00总览` 是否套用九章骨架

- 备选项：甲 用索引结构；乙 套 [[01交接文档写作格式-2026-10-05]] 第 3 章的九章骨架。
- 影响：乙会为一份索引强行填出交付物指纹、回滚与恢复等无内容章节，重复且无信息；甲简洁，把细节留给各文档自身。
- 结论：选甲，并在该文档第 1 章写明它是说明类文档、不套九章骨架。
- 反悔方式：按九章骨架重写，需补交付物指纹与回滚章节。

### 4.3 决策点：`00总览` 第 3 章的颗粒度

- 备选项：甲 每篇 8 条要点（含决策、验证、回滚、环境速查明细）；乙 每篇 2 条，只写定位与主要内容。
- 影响：甲信息全，但与各文档重复、篇幅翻倍；乙简短，细节回原文档查。
- 结论：用户明确要求简写，选乙。
- 反悔方式：压缩前的详细版未入 Git，只能重写。

### 4.4 决策点：库根概要用什么文件名

- 备选项：甲 `README.md`；乙 `库概要.md`；丙 `00库概要.md`。
- 影响：甲在 GitHub 上会被渲染为仓库首页；乙与丙只服务库内导航。
- 结论：用户选甲。
- 反悔方式：改名并同步引用它的双链。

## 6. 回滚与恢复

- 命令在 Windows PowerShell 中执行，执行目录为库根，无管理员权限要求。

```powershell
# 已推送的提交：不改写远端历史，改为追加反向提交
git revert fc3c129

# 仅撤回本地提交（本次提交已推送，撤回前必须先确认远端不接受历史改写）
git reset --soft HEAD~1

# 撤回未提交的 README.md（未跟踪文件，删除即回退）
Remove-Item -LiteralPath '.\README.md'
```

- 何时回滚：提交信息写错、误把不该提交的内容带进历史，或判定 `README.md` 不应放在库根时。
- 回滚会丢失什么：`git revert` 只新增反向提交，历史保留；`git reset --soft` 只动提交记录，改动留在工作区；删除 `README.md` 会丢失该概要与已算出的哈希，需要重写。
- 特别注意：`README.md` 从未提交，删除后无法从 Git 恢复；`00总览` 压缩前的详细版本同样只存在于会话记录中；`01` 改写前的命名规则可从 `fc3c129` 取回（`git show fc3c129:handover/01交接文档写作格式-2026-10-05.md`）。
