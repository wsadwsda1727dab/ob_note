# kb-handover：有条件的快照归档

## 何时使用

用户要求交接或归档，或一个阶段明显收束、需要冻结留痕时。

## 第一步：判断是否创建

正本见 `handover/01交接文档写作格式.md` 第 2.3 节与 `AGENTS.md` 第 5.2 节。满足**任一**触发条件才创建：

- 用户明确要求保存、归档或交接。
- 一个可独立验收的阶段性成果已完成，且关键结论、证据、限制或复现步骤无法仅靠 `handover/当前状态.md` 与已有文档恢复。
- 一项影响后续工作的关键决策已确定，且未来可能需要追溯其依据或被否决的方案。
- 一次复杂故障排查已得出可复现结论，且需要保留完整排查链条。

**默认不创建**：只开启或结束一次会话；只完成普通编辑、常规提交、格式修正或索引更新；`当前状态` 与 `note/` 已完整记录且 Git 足以恢复；事项仍在探索阶段。

判不出来时**默认不创建**，改为更新 `handover/当前状态.md`，并把已验证、有复用价值的结论写入 `note/`（可交给 `kb-maintain`）。

## 第二步：创建时

1. **先读**：`handover/当前状态.md`、`handover/00handover总览.md`、`handover/01交接文档写作格式.md`，必要时读相关历史篇。
2. **命名**：`handover/NN主题-YYYY-MM-DD.md`，`NN` 取本目录当前最大序号加一。
3. **按第 3 章八章骨架写**：1 状态摘要、2 当前工作状态、3 未决事项与下一步、4 决策与理由、5 已验证与未验证、6 回滚与恢复、7 复现方法、8 环境速查。章节不得删除，无内容写「无」并说明原因。
4. **必须写全的四样**：决策点 + 备选项 + 各自影响 + 结论，并记被否决的选项与否决理由；已验证与未验证分栏、推测显式标注；回滚命令标注执行环境；环境速查每条标「已验证」或「推测」。
5. **不抄对话**：试错过程不等于最终方案，未验证假设不等于事实。
6. **同步索引**：更新 `handover/00handover总览.md` 的日期分组与一句话摘要。
7. **同步当前状态**：按 `handover/01交接文档写作格式.md` 第 2.3、9.2 节更新 `handover/当前状态.md`——第 2 段把对应阶段压成一行并指向本篇，第 3 段已被本篇收录的结论压成「结论 + 出处」，第 4 段只更新已被本篇收录、且状态确实发生变化的事项，仍未解决的事项保持现行状态。顺序是先写出本篇、再改 `当前状态`，避免指针悬空；若某条结论是下一步行动的直接依据，仍需写全其成立条件与限制。
8. **人工自查**：逐条执行 `handover/01交接文档写作格式.md` 第 8 章清单。Skill 只负责安排顺序、提醒与汇总，**不得**用自动指纹脚本、自动格式审查或「Skill 已运行」替代人工逐条检查。
9. **未决事项**：本篇记录的是交接时点的状态；当前口径只在 `handover/当前状态.md` 维护，不在两处双写。

## 第三步：创建后

- 该篇即冻结：只有元信息「最近更新」与「未决事项与下一步」章可改（正文见 `handover/01交接文档写作格式.md` 第 2.3 节），事实、格式或结构性遗漏属例外更正。可改范围不等于必须改：形成后才闭环的未决项**不补删除线、不回写第 3 章**，闭环结论记入 `handover/当前状态.md` 第 4 段。
- 不因后续进展回写冻结正文；新阶段变化记入 `handover/当前状态.md`。
- 不提交、不推送；提交须用户明确要求。
