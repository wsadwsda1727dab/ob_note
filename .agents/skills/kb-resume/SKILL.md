# kb-resume：恢复当前工作状态

## 何时使用

新会话接手本库任务、用户要求「接着上次做」、或需要判断「现在停在哪里」时。

## 执行步骤

1. **读入口**：`AGENTS.md` 第 2 章 → `README.md` → `handover/当前状态.md`。不要为了解全库而通读 `note/` 与 `handover/`。
2. **读骨架规则**：`handover/01交接文档写作格式.md` 第 9 章。本篇的六段式与维护规则以该章为正本，本 Skill 不另立骨架。
3. **按第 9.3 节逐项核对**，不一致以**最新证据**为准：
   - 当前任务、目标与下一步 → 对照实际待办与相关文件。
   - 文件是否存在、路径是否有效 → 检查文件与链接；失效的修指针，保留有价值的旧记录。
   - Git 分支、提交与工作区 → 读 `git status`、`git log`，不信文档里的旧动态值。
   - 关键结论及其依据 → 检查所引用的代码、数据与实验结果；不一致标为「待复核」，不把旧结论直接当现状。
   - 未决事项是否已解决 → 查实际证据而非措辞，有证据才关闭。
4. **按需读取**：沿 `当前状态` 里的链接只读与本任务相关的文档；双链是导航提示，不是读取清单。
5. **回报**：给出「当前任务 / 进度 / 仍成立的结论 / 未决事项 / 下一步」，并显式列出核对中发现的不一致与待复核项。

## 边界

- 只读为主。核对发现的偏差可以直接修正 `handover/当前状态.md`（它不冻结），但**不得**改写历史交接文档。
- 不自行创造骨架、不把 `当前状态` 改成纯指针索引，也不把历史快照的内容搬进来。
- 不提交、不推送；需要时按 `note/10提交与文档同步规则.md` 走流程。
