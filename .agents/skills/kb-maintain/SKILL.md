# kb-maintain：沉淀长期知识

## 何时使用

一次任务产生了以后还会复用的结论、方法或环境事实，需要写进 `note/` 时。

## 判断

先问「以后还能用吗」：

- 以后应该怎么做 → 写进 `note/`。
- 过去某阶段发生了什么 → 不写这里，交给 `kb-handover` 或 `handover/`。
- 只是本次的进度或临时状态 → 写进 `handover/当前状态.md`，不新建笔记。

## 执行步骤

1. **先查重**：读 `note/00note总览.md`，确认是否已有同主题文档。已有就**修改或扩展**它，不新建重复文档。
2. **读规范**：`note/05Markdown规范.md`（格式）与 `handover/01交接文档写作格式.md`（若同时涉及 `handover/`）。
3. **写入**：遵守一个 H1、H2 连续编号、章节末尾 `---`、代码块标语言、中文与数字之间留空格、UTF-8 无 BOM + LF。
4. **同步索引**：新增、改名或明显改变职责后，更新 `note/00note总览.md` 的分类、简介与双链；改名按 `note/05Markdown规范.md` 第 7 章更新全部引用。
5. **不写易变事实**：不写「本文件已提交」「当前有几个文件未提交」「这是第几次提交」这类会随提交失效的表述，改为指向 `git status`、`git log`。
6. **不写敏感值**：token、密码、私钥、cookie、内网 IP 与主机名用占位符；提交前按 `note/10提交与文档同步规则.md` 第 4 章扫描。

## 边界

- 最小改动：只改与任务相关的内容，不顺手重构、不重排已有编号。
- `note/` 里的规则文档属长期知识的一部分，不因为它是「规则」就挪到别的目录。
- 不提交、不推送；提交须用户明确要求，且先走「改完 → 同步 → 检查 → 提交」。
